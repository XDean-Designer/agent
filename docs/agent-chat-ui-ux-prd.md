## 1. 概述

### 1.1 目标

用统一的视觉语言与交互质感呈现 **AI Agent 对话窗口**（半屏 Sheet / 全屏），使价目结果卡、开单确认卡、追问白卡、输入条等组件在移动端具备 **轻拟物、品牌粉紫氛围、iOS 级动效质感**，并可被前端完整还原。

### 1.2 范围边界

**本文包含**

- Agent 窗体双态（半屏 / 全屏）的布局、背景、圆角、层级
- Header、会话区、Composer 的视觉与交互态
- 聊天气泡、思考态、功能结果卡（价目 / 开单）、追问白卡、Toast、滚动提示
- Design Tokens、按钮 / Chip 体系、动效规格、资源清单、验收清单

**本文不包含**

- 业务规则、接口、数据模型、审批/开单算法
- 桌面预览壳（左侧原型导航、深色舞台背景）的产品化要求  
  （半屏下「首页背景 + 遮罩」作为 Agent 半屏语境的一部分，见 §3）
- 文案内容策略（仅标注字号/颜色；示例文案可替换）

### 1.3 还原原则

1. **数值优先**：以本文 Token 与组件表为准；原型与本文冲突时以本文为准，并回改原型。
2. **态完整**：每个可交互控件至少覆盖默认 / 按压 / 选中（若有）/ 弱化（若有）。
3. **动效可测**：曲线、时长、位移、缩放均给出数值；支持 `prefers-reduced-motion`。
4. **功能卡 ≠ 气泡**：价目 / 开单结果使用「轻拟物白卡」；Agent 短文本使用「会话白卡（不对称圆角）」；用户消息使用粉红气泡。

## 2. 设计原则

| 原则 | 说明 |
|------|------|
| 品牌氛围 | 粉—紫—暖杏光斑与渐变，避免冷灰科技风、避免紫色扁平仪表盘感 |
| 轻拟物层次 | 白卡 + 极淡描边 + 柔和投影 + 顶栏浅色渐变，区分「系统结果」与「聊天」 |
| 信息层级 | 标题 15–18 / 正文随字号档 / 辅助 11.5–12；金额用 tabular-nums + 加粗 |
| **同时可见信息尽量少** | 一屏只给 1 个主问题；细节收进手风琴 / 折叠 / 名册，按需展开，展开时也只开一层 |
| **无原生下拉** | 所有选择用 Chip、分段按钮、图标钮完成；禁止 `<select>` 与系统弹层选择器 |
| **可预期闭环** | 任何可编辑处都有即时反馈：进度条、摘要回写、禁用态与一句原因 |
| iOS 质感 | Spring 曲线、短按压缩、卡片升起入场、HUD 毛玻璃 Toast；禁止夸张弹跳与长循环装饰动画 |
| 触控友好 | 主按钮高度 ≥ 34pt，底栏操作区 min-height 36；Chip 可多行折行，间距 8 |

## 3. 画布与双态窗体

### 3.1 画布

| Token / 属性 | 值 |
|--------------|-----|
| 逻辑宽 `--lw` | 390px |
| 逻辑高 `--lh` / 默认 `--mobile-h` | 844px |

### 3.2 半屏模式 `mode-sheet`

**窗体**

- 定位：贴底；`top: 23%`，`bottom: 0`，高度随可视区伸缩
- 圆角：`16px 16px 0 0`
- 底色：实色白 `#ffffff` + 纵向多段浅灰粉渐变（保证不透明，不被首页透出）

**面板渐变（自上而下）**

| 停靠 | 色 |
|------|-----|
| 0% | `#f5f3f1` |
| 8% | `#f6f1f3` |
| 22% | `#f1f1f3` |
| 42% | `#ebebed` |
| 58% | `#e8e8ec` |
| 78% | `#efeff1` |
| 92% | `#faf7f8` |
| 100% | `#ffffff` |

**光斑层 `agent-glow`（叠在底上，边缘透明）**

1. `radial-gradient(190px 122px at 33% -2%, #FFE9F0 → transparent 72%)`
2. `radial-gradient(142px 122px at 114% 0%, #F3E6FA → transparent 72%)`
3. `radial-gradient(238px 238px at 84% 118%, #F6DBE4 → transparent 72%)`
4. `radial-gradient(164px 94px at 15% 92%, #F3E6FA → transparent 75%)`

**半屏语境背景（窗体后方）**

- 首页图：全画布 cover，顶对齐
- 遮罩 scrim：`rgba(0,0,0,.75)`，半屏下可见（opacity 1）
- 全屏下首页图与 scrim：opacity 0 + 不可见（`visibility: hidden`）

### 3.3 全屏模式 `mode-fullscreen`

**窗体**

- `top: 0`，高度 100%，圆角 0
- 背景渐变（165deg）：

| 停靠 | 色 |
|------|-----|
| 0% | `#fae7ed` |
| 14% | `#f7eef8` |
| 32% | `#f1f1f3` |
| 52% | `#ececef` |
| 72% | `#f0f0f2` |
| 100% | `#f8eef5` |

**光斑**

1. `240×170 at 10% -2%`，粉 `rgba(255,210,220,.9)` → 透明 62%
2. `280×190 at 94% 6%`，紫 `rgba(230,210,245,.75)` → 透明 58%
3. `300×220 at 70% 108%`，`rgba(246,219,228,.5)` → 透明 62%

### 3.4 双态切换动效（视觉）

| 属性 | 时长 | 曲线 |
|------|------|------|
| `top` / `height` | 420ms `--dur-sheet` | `--ease-spring` `cubic-bezier(.22,1,.36,1)` |
| `border-radius` / 背景色 | 420ms | `--ease-out` `cubic-bezier(.32,.72,0,1)` |
| scrim / home-bg opacity | 420ms | `--ease-out` |
| 切换过程中机器人 | 短暂 `scale(1.02)`，约 450ms 内恢复 | 同 sheet 时长 |

## 5. 全局结构

自上而下三层（均在 Agent 内）：

```
┌─────────────────────────────────────┐
│ Header（机器人 + 问候 + 操作）        │  flex:none
├─────────────────────────────────────┤
│ Messages Shell（可滚动会话）          │  flex:1
│   └─ Messages + Scroll Hint         │
├─────────────────────────────────────┤
│ Composer（输入条）                    │  flex:none
└─────────────────────────────────────┘
```

- 会话层背景透明，灰度来自面板渐变本身，**不再套一层独立浅灰卡片**。
- Messages 内边距：`6px 16px 28px`；纵向滚动，细滚动条。

### 8.9 左滑删除（隐蔽入口）

> 删除是低频且有风险的动作，**不得在列表上新增任何常驻图标、按钮或「⋯」菜单**。入口只在左滑时露出，常态完全不可见。

**行结构**

```
<div class="fn-swipe">
  <button class="fn-del">…</button>      ← 动作块，常态 visibility:hidden
  <div class="fn-swipe-track">
    <div class="fn-row">…</div>          ← 原行内容整体左右位移
  </div>
</div>
```

| 元素 | 规格 |
|------|------|
| 滑动容器 `.fn-swipe` | `overflow: hidden`，圆角 12；行内编辑展开时圆角变 `12 12 0 0`；**`touch-action: pan-y`**（竖滑交给浏览器滚动，横滑交给手势代码） |
| 滑轨 `.fn-swipe-track` | `translateX` 位移，`transition: transform 260ms`；拖拽中加 `.is-dragging` 取消过渡并禁用文本选中（`user-select:none`） |
| 动作块 `.fn-del` | 宽 **84**，贴右侧，上下贴满，`z-index` 低于滑轨；无边框、无内边距 |
| 可删除态 | 底 `#c2506a`，白字 12px/600，文案「删除」，上方 17×17 废纸篓图标，图标与文字 gap 3；按压 `#b0465e` |
| 绑卡态 `.is-locked` | 底 `#c9c6ce`，白字，文案「**不可删**」，图标换锁；按压不变色 |
| 常态隐藏 | `.fn-swipe:not(.is-open):not(.is-dragging) .fn-del { visibility: hidden }`，避免行圆角处透出红色 |

**手势参数**

> **输入方式无关**：手势统一由 Pointer Events（`pointerdown / pointermove / pointerup / pointercancel`）接管，手机手指、触控笔、**PC 鼠标按住左键拖动**走同一套判定与阻尼，不存在「只有触屏能删除」的缺口。仅响应主键（`button 0`），右键与中键不参与。

| 项 | 值 |
|----|-----|
| 起手判定 | 位移 < 6px 不响应 |
| 方向锁定 | 横向位移 > 纵向位移 × **1.15** 即判为横滑；判为纵向则本次手势交给页面滚动 |
| 右向阻尼 | 位移 > 0 时乘 **0.22**（几乎拖不动，暗示只支持左滑） |
| 超拉阻尼 | 超过 −84 后每多拖 1px 只增加 **0.18** |
| 吸附阈值 | 松手位移 ≤ −42 → 吸附到 −84（`is-open`）；否则回 0 |
| 指针捕获 | 判定为横滑后 `setPointerCapture`，指针移出列表区域仍持续跟手，并保证收到 `pointerup` |
| 中断兜底 | `pointercancel` **与 `pointerup` 同路径提交吸附**（不弹回）：鼠标长拖时浏览器可能因原生拖拽接管而取消指针序列，此时按当前位移照常吸附 |
| 原生拖拽 | `dragstart` 在 `.fn-swipe` 内一律 `preventDefault`，避免拖出链接 / 文本幽灵图打断手势 |
| 文本选中 | `.fn-swipe` 常驻 `user-select:none`，鼠标长拖不产生蓝色选区 |
| 同时展开 | **全局同一时刻只允许一行滑开**；滑动新行自动收起旧行 |
| 收起时机 | 点击该行、点击其它行、点击空白、按 `Esc` |
| 点按已滑开的行 | **只收起，不连带展开行内编辑** |
| 拖拽尾随 click | 拖拽结束后 **150ms** 内的 click 视为手势残余并忽略；**动作块 `.fn-del` 例外放行**，保证「拖开→立刻点删除」不被吞；抑制窗口在下一次 `pointerdown` 时清空 |
| 禁用条件 | ① 任一行处于编辑态（避免删除时静默丢弃未保存改动）；② 手势起点落在左缘 **24px** 内（让位导航手势）；③ 起点在 `.fn-inline` 或动作块 `.fn-del` 内 |

> **关键：指针捕获会改变尾随 click 的 target**
> 调用 `setPointerCapture` 后，拖拽结束时浏览器派发的那一次 `click`，其 `target` 是**捕获元素（列表容器 `.fn-list`）**，而不是行内节点。若「点击空白处收起」只按 `target.closest(".fn-swipe.is-open")` 判断，这一次 click 会被误判成「点了空白」，导致**刚滑开的行在松手瞬间立刻弹回、根本点不到删除按钮**。
> 因此列表内 click 与 `document` 级 click **两处都必须先经过同一个抑制判定** `swipeClickSuppressed(e)`，再退回 target 判定。只做行内那层、漏掉 `document` 那一层，就会复现 PC 端「一松开就弹回」。


**绑卡拦截**

- 数据第 7 位为绑定的会员卡数量 `cardCount`，`> 0` 即不可删除
- 绑卡行照常可以左滑（不隐藏入口，避免用户以为是 bug），但动作块显示灰底「不可删」

**计算与展示口径**

> 本节只描述**界面上数值如何排布与联动**，供还原使用；`提成率`、`跟随` 等属于结算口径的既有规则，不在此重新定义。

- 业绩基数 = 本单应付价（原价 − 券，演示 ¥298.00）；**原价或实付价由系统「业绩设置」决定，本卡只做本次开单的微调**
- **每人业绩独立取同一基数，不因多人而均分**；提成 = 个人业绩 × 个人提成率
- 提成率仅作初始值来源（Tony薛 30% / 何苏叶 25% / 陈嘉怡 20% / 赵鹏 15% / 周小雨 10%），**界面上不展示任何百分比**
- 工位数量固定 3 个（大工 / 中工 / 小工），**工位内不再有比例、也不再有工位金额**
- 同一员工可同时出现在多个工位；数值只在首次出现处展示一份，后续工位标「同单」
- 改「业绩」**不联动**提成；改「提成」也不回写业绩，两者完全独立
- **跟随规则**：改总价 / 用券 / 取消用券后，**未手改过**业绩或提成的员工自动按新应付价重算；**手改过的员工锁定不动**（`touched`）
- **不展示全单业绩/提成合计**（Hero 只有金额）
- 工位无人不阻断批准，也不再多一句提示：工位名后已显示「未分配」、摘要里该组显示「未分配」，保持安静

- 删除某笔后，该方式立即回到选择器列表，说明行同时还原为按钮

**加笔逻辑（交互结果）**

1. 首次选定的收款方式（追问卡「支付方式」）→ 金额**等于应付全额**
2. 之后每次「添加收款方式」→ 新笔金额**恒为 0.00**，并自动聚焦选中，由用户自行填写
3. 取消旧的「新笔自动带入剩余」与「已收满对半拆开」两条规则

**混合收款自动补齐（本次新增，核心交互）**

> 目标：任意时刻各笔相加 **恒等于应付总额**，用户只需改一笔。

| 场景 | 行为 |
|------|------|
| 改某一笔金额 | 由**除当前项外金额最大的一笔**吸收差额，实时联动；大额笔保持稳定、小额笔承担浮动 |
| 只有 1 笔 | 不联动，保留「欠款 / 超收」校验（进度条与批准按钮给反馈） |
| 3 笔及以上 | 仍只动「金额最大的一笔」，其余笔保持原值；编辑项上限 = 应付 − 其余笔合计 |
| 编辑值超过应付 | **上限锁定**：输入被夹到「应付 − 其余笔合计」，吸收方落到 0.00，绝不出现超收 |
| 删除某一笔 | 该笔金额并入剩余金额最大的一笔，总额立刻回到应付；删到只剩 1 笔时不再补齐 |
| 改应付（Hero 实收价 / 用券） | 若原本收满，由**金额最大的一笔**吸收差额，其余笔不动 |

- 联动时机：**输入时实时**（`input` 事件），光标停在正在编辑的输入框内不被夺走；失焦时再统一归一化为两位小数
- 联动通过直接写另一笔的 `input.value` 实现（不重建 DOM），并同步刷新：进度条宽度与文案、分区摘要、批准按钮可用性
- 金额只做两位小数四舍五入，避免浮点误差导致「差 0.01 未收满」

**批准按钮联动**

- **仅收款条件**拦截：未收满或超收 → 「批准」置灰（`--btn-muted` 描边与字色，非填充），`disabled`

- 金额输入时只做轻量刷新（进度、摘要、提示、按钮态），**不重建输入框**，保证焦点与光标不丢；失焦时归一化为两位小数

## 11. Composer（输入条）

### 11.1 容器

- 外层 padding：`10 12`，底部另加 `kb-h + safe-pad`
  - `--kb-h`：软键盘遮挡高度（逻辑像素），键盘收起时为 0
  - `--safe-pad`：安全区底垫；**键盘打开时归 0**（键盘已盖住 Home 条，再叠加会多出一道空隙），收起时回到 `--safe-bottom`
- 半屏：外层背景透明
- 全屏：底部白色渐入蒙层，避免内容顶到输入条时发脏
- 真机：可用更实的白渐变托底（`0% 透明 → 28% #fff`）

### 11.4 软键盘与视口（移动端）

> 目标：键盘弹出时**窗体尺寸与位置完全不变**，只有底部输入条贴着键盘上移，会话区自然变矮。

**viewport 声明**

```
<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=overlays-content">
```

- 必须用 `overlays-content`：键盘只「覆盖」可视区，不改变布局视口，Android 与 iOS 行为才一致
- 禁止 `resizes-content`：它会让布局视口一起缩小，`innerHeight` 与 `visualViewport.height` 同步变化，键盘高度算不出来

**基线高（窗体高度的唯一来源）**

| 项 | 规格 |
|----|------|
| 定义 | 非键盘状态下的可用高度；`--mobile-h` 与舞台高度都取它 |
| 采样 | 进入移动态、或横竖屏切换时重新采样 |
| 键盘判定 | 同时满足：① 当前焦点在 `input / textarea / select / contentEditable`；② 高度收缩 ≥ **140px** |
| 键盘态 | 冻结基线（`kbState.active`），窗体尺寸不再跟随可视高 |
| 恢复 | 高度回到基线 − 40px 以内即解除冻结，重新跟随（地址栏伸缩等正常变化不被当成键盘） |
| 禁止 | 用收缩后的可视高直接算 `--mobile-h`（会让整窗被压扁）；用 `innerHeight − vv.height` 算键盘高（在 `overlays-content` 下恒为 0） |

**键盘高度 `--kb-h`**

`--kb-h = (基线高 − 当前可视高) / scale`，仅在键盘态下取值，否则为 0。

**输入框避让**

| 项 | 规格 |
|----|------|
| 触发 | 编辑器获得焦点，或 `--kb-h` 由 0 变为正值 |
| 延迟 | 90ms 后首次校正，280ms 后二次校正（覆盖键盘动画收尾位移） |
| 作用范围 | **只改 `.messages` 的 `scrollTop`**，不移动窗体、不移动舞台 |
| 目标位置 | 编辑器目标落在会话可视区**中部**；已完整可见时只在贴边（距边缘 < 24px）才微调 |
| 适用编辑器 | `.od-hero-input` / `.st-input` / 价目行内 `input` / 收款金额输入 |

**验收口径**

- 键盘弹出前后：`#frame` 的高度与 `top` 完全一致
- 输入条底边 = 可视区底 − 12px（不再额外叠加安全区）
- 键盘收起后：`--kb-h` 归 0，`--safe-pad` 恢复安全区，输入条回落原位

## 12. 动效规格（编排级）

### 12.1 入场 / 退场

| 名称 | 关键帧 | 时长 | 曲线 |
|------|--------|------|------|
| rise 入场 | y+10、opacity0、scale.985 → 复位 | 340ms | ease-out |
| reply 入场 | x+12、opacity0、scale.97 → 复位 | 340ms | ease-out |
| exit 退场 | 复位 → y+6、opacity0、scale.985 | 200ms | ease-out |
| chip 错峰 | y+6 → 0 | 300ms，delay 40ms×n | ease-out |
| pill pop | scale 1→1.08→1 | 420ms | spring |
| success flash | 阴影闪绿 | 550ms | ease-out |

### 12.2 界面切换编排（视觉顺序）

1. **追问 → 草稿卡**：选中 Chip 高亮约 160ms → 追问卡 exit → 右侧回复泡 reply 入场 + 开单卡 rise 入场  
2. **批准 → 成功**：卡面 success flash + pill pop；同卡内容切换为成功只读；追问白卡 rise + Chip 错峰  
3. **拒绝**：开单卡 exit → 追问白卡 rise（含重新开单）  
4. **半屏 ↔ 全屏**：窗体几何 + scrim + 机器人联动（§3.4）

### 12.3 禁止项

- 全程循环晃动、彩色光晕脉冲超过思考态必要范围
- 每个按钮不同贝塞尔
- 大面积视差 / 3D
