## 1. 文档信息与范围

### 1.1 目标

用统一视觉语言呈现 **AI Agent 全屏对话窗**：首页提醒进场 → 全屏会话 → 价目 / 卡管理 / 开单 / 自助归档等功能结果，在移动端具备轻拟物、品牌粉紫氛围与可测动效，供前端像素级还原。

### 1.2 In / Out

**In（本文包含）**

- 双态窗体：`home` ↔ `fullscreen` 的布局、背景、层级与切换
- 首页 TAB、B2 图标进出提醒、归档 tip 气泡
- Agent 壳：Header / 会话区 / Composer / 滚动提示
- 聊天气泡、思考态、Toast、Chip、折叠区
- 价目表、**信息表 InfoTable** 规范、卡管理（会员卡模板）、开单确认卡（含单项目 / 多项目）、自助归档确认卡的表现层规格
- Design Tokens、动效、P0 验收清单

**Out（本文不包含）**

- 接口、库表、审批后台、开单算法与业务规则实现
- 桌面预览壳（左侧导航、右侧 PRD 同步窗、深色舞台）的产品化要求（导航 / 同步窗为演示辅助，见 §2.2、§1.4）
- **半屏 Sheet 模式**（已废弃；无 `mode-sheet`、无「展开全屏」、无半屏入口）
- 圆环 / 圆形放大进场（已废弃；仅保留 B2 图标进出）

### 1.3 还原原则

1. **数值优先**：Token 与组件表为准；与原型冲突时先对齐本文再回改原型。
2. **态完整**：可交互控件至少覆盖默认 / 按压 / 选中（若有）/ 禁用或弱化（若有）。
3. **动效可测**：曲线、时长、位移均给数值；尊重 `prefers-reduced-motion`。
4. **功能卡 ≠ 气泡**：价目 / 开单 / 归档结果用轻拟物白卡；Agent 短文用会话白卡；用户消息用粉红气泡。
5. **文档同步**：表现层变更与 PRD 同轮提交，不积压。

### 1.4 体验优化：目标与原则

面向 **小美业店主 / 店员**（术语与软件操作偏弱），且操作常发生在 **顾客做完服务、即将离店** 时——客没有耐心久等。Agent 开单相关能力按下列目标与原则演进；桌面预览右侧「PRD · 同步」窗与演示态对齐本节及对应专章摘要。

#### 目标

1. **又快**：离店窗口内用最少轮次完成开单确认。  
2. **又稳**：缺什么写在界面上；确认卡可改细节，不靠追问回声「改」。  
3. **又听得懂**：店里话、短句、「×× 块」；少用权益 / 储值 / 工位等术语堆砌。

#### 原则

| # | 原则 | 含义 |
|---|------|------|
| P1 | 链路短 | 能合并的追问合并；少进二级页 |
| P2 | 白话 | 金额与提示口语化；一步一句 |
| P3 | 主路径清楚 | 每步一个主操作；次要入口弱化 |
| P4 | 说 / 点双通道 | 文案点明可说；演示「试试说一句」 |
| P5 | 防错不拖堂 | 缺项状态写在卡上；细节纠错放确认卡，少靠 Toast |
| P6 | 先结果后细节 | 追问期零券/权益/复杂编辑；确认卡细节默认折叠 |
| P7 | 先单独后合并 | 选项多/可进子页的字段单独问；选项少、不进子页的字段合并问 |

#### 已落地摘要 · 智能追问（v3.12）

- **单独（先）**：服务项目（可「换一个」进在售短列表）→ 顾客（`男散客` / `女散客` + **选择会员** → 选择顾客页，仅会员）  
- **合并（后）**：同一张追问卡内 **谁做的** + **怎么收钱** 始终同显、同时可点；主文只读带「按 ×× 块」（**不**再追问价格）；无「先选谁做的」门槛  

- 全店统一会员池 `STORE_MEMBERS`；「开单 · 三项」跳过单独步，直接进合并卡  
- **无**回声旁「改」；「试试说一句」；进卡半句提示；改价在确认卡  

#### 已落地摘要 · 离店加速（自 v3.10，并入合并卡）

- 点 1 人即选中；「还要加人」；「稍后补」；收款与员工同卡同时可选  
- 金额白话「×× 块」只读提示；进卡半句提示；确认卡复杂区默认折叠  

#### 入口角色（演示）

| 入口 | 角色 |
|------|------|
| 开单（主） | 主演示：先单独（项目/顾客）→ 后合并（员工+收款） |
| 开单 · 三项 | 对照：信息半齐，直接合并卡 |
| 价目 / 归档 / 卡管理 | 其它能力对照 |

#### 归档 tip 气泡 `#tabTip`

| 规则 | 说明 |
|------|------|
| 文案 | 1 笔：「有待归档自助单」；多笔：`N 笔待归档` |
| 出现 | 首页且存在**尚未提示过**的 pending 自助单 |

| 新单 | 「模拟新自助单」写入新 pending → 回首页可再弹 |

- 价目 `#fnToast`、开单/归档 `#orderFlowToast`：底中 HUD，可带「撤销」

- 追问支付 / 工位员工 / 分类 tab：描边浅蓝底；选中加 `--btn-fill` + 加粗

### 3.5 动效与反馈小结

| 场景 | 反馈 |
|------|------|
| 按压 | 主控 `scale(.97–.99)`，`--dur-press` |
| 卡片入场 | 上移 + 淡入，`--dur-enter` |

| 禁用主按钮 | 降透明 + 不可点；文案或 hint 说明原因 |
| 金额 | `tabular-nums` + 加粗 |

## 4. 信息表 InfoTable（表格类信息展示）

由价目表固化的可复用模式。凡「分类筛选 + 列表行左文右数 + 底栏操作」的 Agent 结果，优先套用本规范。参照实现：`#sessionCard`（价目）。

**不适用**：异形卡面（如卡管理模板色卡）、开单确认卡分层编辑——那些不是 InfoTable。

### 4.1 结构（自上而下）

| 层 | 何时 | 规格 |
|----|------|------|
| 卡头 | 建议有 | 左图标 + 标题；右状态 pill（如「18 在售 · 4 停售」） |
| 分类 Tabs | **有分类时** | 顶栏横向蓝系 chip tab（现 `.fn-tab`）；选中 = `--btn-fill` 底 + 描边 + 字重；可折行；**禁止**原生 `<select>` |
| 行列表 | 必有 | 灰底横条（现 `.fn-row`）：**左文字信息、右数值**；整行默认只读 |
| 列表附属 | 可选 | 「展开剩余」、空态、左滑删除等行级操作 |
| 底栏操作 | **有操作时** | 右主蓝按钮（`.fn-act-primary`）+ 左/次幽灵（`.fn-act-ghost`） |

### 4.2 行规格

| 区域 | 内容 |
|------|------|
| 左 | 主文案；可加左侧状态点 / 弱标签；ellipsis |
| 右 | 数值，`tabular-nums`；金额带 `¥` |
| 弱化 | 停用/无效行降透明（如 `.is-off`） |

视觉锚点：灰底 `#faf9fb`、浅描边、圆角约 12、水平 padding 与现价目一致；一屏一种表，不在行内堆多列编辑。

### 4.3 Token 挂接

- Tab / 主按钮：AI 蓝按钮语汇 `--btn-*`
- 正文随 `--fs-body`；辅助色 `--muted`

### 4.4 实例 · 价目表

1. 用户气泡 → 思考 → Agent 短文 → InfoTable 结果卡  
2. Tabs：全部 / 洗吹 / 剪发 / 染发 / 烫护  
3. 行：状态点 + 名 | `¥` 价；只读；左滑删除 + 确认弹层  
4. 底栏：「只看在售」幽灵 · 「去价目表管理」主按钮（Toast 示意）  
5. 空态：`.fn-empty`

### 4.5 其它遵循处

- 归档确认卡内 **更换项目** 选择列表：分类 tabs + 在售行左名右价 + 置顶「快捷开单」，同行样式。

## 6. 开单

### 6.1 流程（表现层）

**主演示（侧栏「开单（主）」· 先单独后合并）**

```
用户「帮我开一单泡泡染。」→ 思考 → Agent 短文
  → ① 单独：服务项目 → 回声（无「改」）
  → ② 单独：顾客 → 回声（无「改」）
  → ③ 合并卡：谁做的 + 怎么收钱（主文只读带价）→ 回声 → 半句提示 → 确认卡
```

| 步 | 类型 | 文案要点 | 入口 |
|----|------|----------|------|
| 项目 | 单独 | 「项目按 泡泡染 开，对吗？」；选定后写入价目价 | `对，就这个` · `换一个`（在售短列表，chip 可带「×× 块」区分） |
| 顾客 | 单独 | 「先说下是哪位顾客？」 | `男散客` · `女散客` + **`选择会员`**（子页） |
| 合并 | 同卡 | 「…按 ×× 块。选一下员工和收款方式就行。」（金额**只读提示**） | **员工**与**收款**同卡同时可选：点 1 人即选 / `还要加人` / `稍后补`；主支付微信/支付宝/现金，「更多」含会员卡；未选人也可点支付（确认卡可补员工） |

追问回声 **不**显示「改」。纠错：重开演示，或进确认卡后改价/员工/收款。

**进卡前提示（半句）**：会员卡「先用卡里的钱付；其它下一步再选。」/ 其它「好，按这个收；有优惠下一步再选。」

**确认卡**：追问期无券/权益/复杂编辑；进卡后员工明细、优惠、权益 **默认折叠**；仅会员卡默认展开收款。

**对照（开单 · 三项）**：跳过项目/顾客，直接进入合并卡。

### 6.3 确认卡（`data-phase="draft"`）

| 区块 | 表现 |
|------|------|
| 头 | 「开单确认」+ pill「待确认」 |
| Hero | **实付**大数字 = `effectivePayable`（券后应付再套项目权益折算）；可点改；项目名（多项用「 · 」连接）；顾客 + 会员副文；优惠券 / 权益 chip |
| 服务员工 | 见下「单项目 / 多项目」；含「选择权益」入口 |
| 优惠 | 固定金额券；选用或「不用券」后 **自动收起** 本区，并重算 Hero / 收款 |
| 收款 | 支付行可改金额；**会员卡 = 储值**（直接输金额）+ 次级行 **赠金**；**不在此选项目权益** |
| 底栏 | 「拒绝」（危险幽灵）+「确认开单」（主按钮） |
| Hint | 说明可改项；确认才提交 |

**无券无权益基准**：单项目 Hero `¥298.00`；业绩合计与提成按工位费率演示。

#### 单项目

- 服务员工区为灰底块：大/中/小工 chips、业绩与提成可编辑
- 块内底部 **「选择权益」** 折叠入口（适用：折扣 / 计次 / 不限次，按项目过滤）
- 再点已选权益可取消

#### 多项目（≥2 项 · 侧栏「开单 · 三项」）

- 服务员工与项目权益**按项目各自设置、分别计算**后汇总实付；收款为本单合计
- **信息层级**：L1 项目（最大字重 + 左侧色条卡片 + 价格）→ L2 工位（缩进、弱标签色）→ L3 人名与业绩/提成（再弱、浅底行）
- 每个项目灰卡底部各自有 **「选择权益」**；只列出适用该项目的权益

#### 交互细则

| 操作 | 预期 |
|------|------|
| 工位名册内增 / 减一名员工 | 该工位胶囊名册 **立即收起** |
| 选中某张券或「不用券」 | 「优惠」折叠区 **自动收起** |
| 追问或收款中选「会员卡」 | **停留在收款区**（`orderOpenSec=pay`），不跳到项目/员工区 |
| 改项目权益或优惠券 | Hero 实付与收款金额按 `effectivePayable` 重算对齐 |

### 6.4 项目权益 vs 会员卡储值（拆分）

二者互不混用：权益改应付；会员卡只是支付渠道。

**A. 项目侧「选择权益」**（服务员工灰卡内；无彩色类型标）：

| 类型 | 展示名示例 | 适用过滤（演示） | 行为要点 |
|------|------------|------------------|----------|
| 计次 `times` | 泡泡染次卡 | 仅「泡泡染」等匹配名 | 该项目有效应付 → 0 |
| 折扣 `discount` | 持卡会员 9 折 | 各项目可用 | 该项目应付 × rate；收款他方补齐折后差额 |
| 不限次 `unlimited` | 护理不限次卡 | 仅「头皮护理洗」等匹配名 | 该项目有效应付 → 0 |

选中态：`.mb-pick.is-on`。入口未选时文案「选择权益」；已选显示权益名 + 额度示意（如「9折」「1次」「不限次」）。

**B. 收款「会员卡」= 储值支付**

```
会员卡 · 储值    ¥200     ← 本笔划卡总额（可改，参与收满对齐）
  赠金           ¥ 50     ← 次级行；右侧提示「本金 ¥150」
```

- `本金 = 会员卡金额 − 赠金`；改赠金不改总额（此消彼长）；赠金 ∈ [0, 会员卡金额]
- 改会员卡总额时：若赠金超出则压到上限
- 归档只读时：可展示赠金 / 本金构成行

### 6.5 成功 / 拒绝

| 结果 | 表现 |
|------|------|
| 确认 | pill → 已开单类成功态；跟进短文 + 操作 chips；Toast |
| 拒绝 | 卡收起或失败文案；流程结束，可再开演示 |

## 7. 自助归档

### 7.1 提醒 → 待办

1. 首页 tip（§3.2）→ 点 AI 进全屏并进入归档 demo（若有未提示 pending）
2. 会话内：Agent 引导 + **待归档订单 chips**（顾客 / 金额 / 时间）
3. 点某一笔 → 打开归档确认卡（与开单共用 `order-card` 壳）

### 7.2 归档确认卡

对齐开单确认的信息架构，差异如下：

| 项 | 归档 |
|----|------|
| 标题 / pill | 「归档确认」类 +「待归档」 |
| Hero | 已收金额为主；散客仅主文「男/女散客」（**无**重复灰字副文）；项目行可「更换」 |
| **支付** | **只读**：展示已收渠道与金额；会员卡若含赠金则只读展示赠金/本金 |
| 工位 | **与开单相同**：可编辑大中小工员工、业绩、提成（归档无「选择权益」） |
| 身份工具 | 见下表 |
| 项目更换 | 项目名右侧小蓝字「更换」→ 选择页，见下 |
| 底栏 | 「拒绝」+「确认归档」 |

**Hero 身份按钮**

| 组别 | 按钮 | 样式 | 图标（内联 SVG，非 emoji） |
|------|------|------|---------------------------|
| 身份 · 主 | 切换为会员 | 实心浅蓝（`is-id-primary`） | **王冠** |
| 身份 · 次 | 切换为女/男散客 | 同形浅蓝底描边（`is-id-secondary`） | ♀ / ♂ 性别标 |
| 身份 · 次 | 切换为散客（会员态） | 同 `is-id-secondary` | 可用女标示意 |

**项目行与选择页**

- 行内顺序：`项目名` →（可选）`智能补全` 标 → 小蓝字 **「更换」**；间距 **6px**；任意当前项目均可更换
- 点「更换」展开/收起选择页（**不再**点项目名整行、**不再**另设「改为快捷开单」内容链）
- 分类 tabs：全部 / 洗吹 / 剪发 / 染发 / 烫护（与价目表同源 `CATS`）
- 列表：当前分类下 **在售** 价目行（名 + ¥价，数据同源 `PRICE_ROWS`）
- 置顶一项：**快捷开单**（闪电标）+ 副文「不选项目，直接收款」——选中即 `contentMode=quick`
- 选中价目项：回填项目名/分类，`smartItem=false`，收起面板

- **切换为会员**：展开会员列表（演示 4 人：姓名 / 尾号 / 会员类型）；选中后回填会员信息，可尝试历史工位回填
- **切换为女/男散客**：在男女散客间切换；清空会员字段；主文已含性别，无灰字重复

演示造数示例：李女士 ¥198 微信；男散客 ¥88；王小姐 ¥320（微信+会员卡）等。

### 7.3 已归档

确认后该单 `status: done`；从待办 chips 消失；Toast「已归档」；pill 成功态。拒绝则返回待办列表。
